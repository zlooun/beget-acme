# Beget ACME

Автоматический выпуск и продление сертификатов Let's Encrypt для доменов с DNS у Beget.
Поддерживает домены, поддомены и wildcard, работает локально или в Docker без root.
Один экземпляр обслуживает один сертификат с несколькими именами.

[English](docs/en/README.md) · [Docker Hub](https://hub.docker.com/r/zloun/beget-acme) · [Релизы](https://github.com/zlooun/beget-acme/releases) · [Issues](https://github.com/zlooun/beget-acme/issues)

Образ `zloun/beget-acme` поддерживается автором проекта для Linux `amd64` и `arm64`.
Проект независимый: это не официальный продукт Beget и не Docker Official Image.

## Быстрый старт

Потребуются домен с DNS под управлением Beget, доступ к его API и исходящие подключения
к Beget, Let's Encrypt и DNS-серверам. Открывать входящие порты 80/443 для выпуска не нужно:
проверка владения выполняется через временные TXT-записи (DNS-01).

> **Перед первым выпуском:** Beget заменяет все записи на конкретном DNS-имени.
> Для `example.com` и `*.example.com` проверьте в панели, что `_acme-challenge.example.com`
> пуст и выделен этому приложению. Для `api.example.com` проверьте
> `_acme-challenge.api.example.com`. Флаг `--accept-dns-replacement` подтверждает эту проверку.
> Не запускайте другой ACME-клиент для тех же challenge-имён одновременно.

Выберите один из способов ниже. Для обоих нужна минимальная конфигурация в файле `.env`
в рабочей папке:

```dotenv
BEGET_USERNAME=your_api_login
BEGET_PASSWORD='your_api_password'
ACME_EMAIL=admin@example.com
ACME_DOMAINS=example.com,*.example.com
```

Замените значения своими. Одинарные кавычки помогают сохранить символы `$` и `#` в пароле
при чтении Compose. Не публикуйте `.env`; разрешите его чтение только нужному пользователю.
Wildcard `*.example.com` не включает сам `example.com` и вложенное имя `api.dev.example.com`.

### Docker Compose

Нужен Docker с Compose v2. Node.js и сборка исходников не требуются.
Команды ниже — для Linux; через интерфейс NAS можно создать те же файлы и каталоги.

**1. Подготовьте рабочую папку и Compose.**

```sh
mkdir beget-acme
cd beget-acme
curl -fsSL https://raw.githubusercontent.com/zlooun/beget-acme/v0.2.0/examples/compose.image.yml -o compose.yaml
```

Вместо `curl` можно сохранить [Compose для готового образа](examples/compose.image.yml)
как `compose.yaml`. Создайте рядом `.env` с четырьмя параметрами выше и добавьте:

```dotenv
BEGET_ACME_IMAGE=zloun/beget-acme:0.2.0
```

**2. Создайте каталоги и назначьте права.** Контейнер по умолчанию работает как `10001:10001`:

```sh
mkdir -p state output
sudo chown 10001:10001 state output
sudo chmod 700 state
sudo chmod 750 output
chmod 600 .env
```

Для другого пользователя задайте `APP_UID` и `APP_GID` в `.env` и используйте те же ID
при назначении прав. На NAS проверьте также ACL. Для rootless Docker учитывайте отображение
ID на хосте. [Подробнее о правах](docs/ru/OPERATIONS.md#пользователь-контейнера-и-права).

**3. Проверьте выпуск в staging.** Тестовый сертификат не предназначен для браузеров:

```sh
docker compose pull
docker compose run --rm beget-acme run --staging --once --accept-dns-replacement
```

Дождитесь успешного выпуска и окончания очистки DNS. Если команда завершилась с ошибкой,
сначала посмотрите [диагностику](#диагностика).

**4. Выпустите production-сертификат и включите автоматическое продление:**

```sh
docker compose run --rm beget-acme run --once --accept-dns-replacement
docker compose up -d
docker compose logs -f beget-acme
```

Переходите к `up -d` после успешного завершения выпуска. Разрешение сохраняется отдельно
для staging и production, поэтому постоянному сервису флаг уже не нужен. `Ctrl+C` в просмотре
логов не останавливает контейнер. Не запускайте `run --once` параллельно с работающим сервисом.

### Локально

Нужны Git и Node.js версии из [.node-version](.node-version) — сейчас `24.22.1`.
Команды `node` и `npm` работают также в Windows PowerShell.

**1. Получите исходники и соберите приложение:**

```sh
git clone --branch v0.2.0 --depth 1 https://github.com/zlooun/beget-acme.git
cd beget-acme
npm ci
npm run build
```

**2. Создайте `.env`** с четырьмя параметрами из начала раздела. Можно создать расширенный
шаблон командой `node dist/cli.js init` и отредактировать его; существующий файл не перезаписывается.
Каталоги `state` и `output` создаются приложением в текущей папке. У пользователя должны
быть права записи; на Linux ограничьте доступ к `.env` командой `chmod 600 .env`.

**3. Проверьте staging, затем запустите production:**

```sh
node --env-file=.env dist/cli.js run --staging --once --accept-dns-replacement
```

После успешного завершения:

```sh
node --env-file=.env dist/cli.js run --accept-dns-replacement
```

`run` остаётся работать в терминале и продлевает сертификат по мере необходимости.
Для постоянной работы после закрытия терминала используйте Docker или
[systemd](docs/ru/OPERATIONS.md#systemd-и-cron). Отдельный `setup` для быстрого старта не нужен.

## Где сертификаты и что происходит дальше

При настройках по умолчанию результат находится в рабочей папке:

```text
output/
  production/current/
    fullchain.pem    # Certificate and intermediate chain
    privkey.pem      # Private key
  staging/current/   # Test certificates, separate from production
state/               # Account keys, approvals and recovery state
```

Подключите `fullchain.pem` и `privkey.pem` к своему TLS-серверу и настройте его reload
после обновления. Для контейнера монтируйте **весь `output` только для чтения**, а не отдельный
`current` или PEM: приложение переключает `current` на новую версию сертификата.
[Готовый вариант для Nginx](docs/ru/NGINX.md).

После успешной проверки приложение ждёт **12 часов**. Продление начинается, когда осталось
меньше **трети фактического срока** сертификата: например, менее 30 дней из 90.
После операционной ошибки следующая попытка — через **1 час**, без отдельного параллельного
таймера и лимита попыток. Требование CA подождать дольше имеет приоритет.

Состояние и время следующей проверки сохраняются между перезапусками. При старте приложение
сначала пытается восстановить незавершённую операцию. Чужие DNS-записи и неоднозначные ответы
API могут потребовать вмешательства: повторы не обходят проверки безопасности.

## Команды и справка

Справка доступна без настроек и учётных данных:

```sh
docker run --rm zloun/beget-acme:0.2.0 --help
node dist/cli.js --help
```

Выберите команду для своего способа установки. Вместо `--help` можно использовать `help` или `-h`.
Для обычных команд используйте один из префиксов:

```sh
docker compose run --rm beget-acme <command> [options]
node --env-file=.env dist/cli.js <command> [options]
```

**Выпуск и продление**

| Команда                       | Что делает                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `run`                         | Выпускает отсутствующий сертификат или продлевает его при необходимости, затем остаётся работать; команда по умолчанию |
| `run --once`                  | Выпускает или продлевает сертификат при необходимости, завершает очистку DNS и выходит                                 |
| `schedule`                    | Автоматически продлевает существующий production-сертификат; первоначальный выпуск не выполняет                        |
| `schedule --once`             | При необходимости продлевает существующий production-сертификат, завершает очистку DNS и выходит                       |
| `issue [staging\|production]` | Однократно выпускает или продлевает при необходимости; по умолчанию staging                                            |
| `renew [staging\|production]` | Однократно продлевает существующий сертификат при необходимости; по умолчанию production                               |

Если подходящий сертификат ещё не требует продления, новый не выпускается — в том числе
при `issue`. `run` и `schedule` включают восстановление незавершённой операции и планирование
повторов; `issue` и `renew` — отдельные операции без этого цикла.

**Диагностика и обслуживание**

| Команда            | Что делает                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------- |
| `status`           | Показывает сроки сертификатов, состояние восстановления и блокировку; только чтение      |
| `doctor` / `probe` | Проверяет Beget и DNS без изменений; `probe` — другое имя той же команды                 |
| `setup`            | Проверяет DNS и сохраняет разрешение локально; не меняет DNS и не создаёт ACME-заказ     |
| `cleanup`          | Очищает принадлежащие журналу DNS-записи и обновляет журнал; нужна исходная конфигурация |
| `journal-clear`    | Аварийно архивирует журнал после проверок пустоты DNS и явного подтверждения оператора   |
| `init`             | Создаёт шаблон `.env`, не перезаписывая существующий файл                                |
| `help`             | Показывает встроенную справку                                                            |

**Флаги**

| Флаг                       | Для каких команд                                                        | Назначение                                                                               |
| -------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `--once`                   | `run`, `schedule`                                                       | Выполнить полный цикл при необходимости и выйти, не запускать следующий                  |
| `--staging`                | `run`, `setup`, `status`, `doctor`, `probe`, `cleanup`, `journal-clear` | Использовать тестовое окружение                                                          |
| `--accept-dns-replacement` | `run`, `schedule`, `setup`                                              | Подтвердить ручную проверку выделенных DNS-имён                                          |
| `--dry-run`                | `issue`                                                                 | Проверить DNS без создания аккаунта, заказа и записи DNS; нужна разрешённая конфигурация |
| `--check`                  | `status`                                                                | Вернуть ненулевой код, если выбранное окружение не готово                                |
| `--json`                   | Все команды, выводящие события журнала                                  | События в JSON; ошибки идут в stderr. Справка и версия остаются обычным текстом          |
| `--version`, `-V`          | Самостоятельный вызов                                                   | Показать версию и выйти                                                                  |
| `--help`, `-h`             | Самостоятельно или с командой                                           | Показать общую справку и выйти, не выполнять команду                                     |

`--once` **не означает «только проверить»**: он дожидается распространения DNS, обработки
заказа CA и очистки в рамках текущего цикла. Если выпуск не нужен — выходит без нового заказа.
При ошибке выходит с ненулевым кодом без ожидания следующего цикла. Сохранённую задержку
после предыдущей ошибки не обходит: возвращает `RENEW_RETRY_DEFERRED`, пока срок не наступил.
Поэтому этот режим подходит и для разового выпуска, и для внешнего планировщика.

Флаги можно ставить до или после команды. У `issue` и `renew` окружение задаётся позиционно:
например, `issue staging` или `renew production`; `--staging` для них не используется.
`schedule` всегда работает с production. Остальные команды с выбором окружения используют
`ACME_ENVIRONMENT` (по умолчанию production) либо `--staging`.

Для повседневной работы достаточно `run`, `status` и `doctor`.
[Условия запуска и аварийные команды](docs/ru/CONFIGURATION.md#команды-и-режимы).

## Настройки

Обязательны только четыре параметра из быстрого старта; Compose с готовым образом также
требует `BEGET_ACME_IMAGE`. Остальное меняйте при необходимости.

| Переменная                         | По умолчанию      | За что отвечает                                               |
| ---------------------------------- | ----------------- | ------------------------------------------------------------- |
| `ACME_DOMAINS`                     | Обязательна       | Имена в одном сертификате через запятую, максимум 100         |
| `ACME_EMAIL`                       | Обязательна       | Контактная почта аккаунта ACME                                |
| `BEGET_USERNAME`, `BEGET_PASSWORD` | Обязательны       | Учётные данные API Beget                                      |
| `ACME_RENEW_BEFORE_DAYS`           | Треть срока       | Продлевать, когда осталось меньше указанного числа дней       |
| `ACME_SCHEDULE_INTERVAL_MS`        | `43200000` (12 ч) | Пауза после успешной проверки                                 |
| `ACME_RETRY_INTERVAL_MS`           | `3600000` (1 ч)   | Пауза после операционной ошибки                               |
| `ACME_ENVIRONMENT`                 | `production`      | `staging` для постоянного тестового сервиса                   |
| `ACME_PRIVATE_KEY_MODE`            | `0600`            | `0640` для чтения ключа настроенной общей группой             |
| `ACME_ACCEPT_DNS_REPLACEMENT`      | Не задана         | `yes` вместо флага для начальной настройки в `run`/`schedule` |

Например, чтобы продлевать менее чем за 10 дней до истечения:

```dotenv
ACME_RENEW_BEFORE_DAYS=10
```

Если параметр не задан, остаётся автоматический порог в треть срока. Не задавайте порог
больше срока сертификата: это приведёт к продлению при каждой успешной проверке.

**Пути и пользователь зависят от способа запуска:**

| Где                              | Переменные                          | По умолчанию          |
| -------------------------------- | ----------------------------------- | --------------------- |
| Локально                         | `ACME_STATE_DIR`, `ACME_OUTPUT_DIR` | `./state`, `./output` |
| Compose, пути хоста              | `STATE_DIR`, `CERTIFICATES_DIR`     | `./state`, `./output` |
| Compose, пользователь контейнера | `APP_UID`, `APP_GID`                | `10001`, `10001`      |

Внутри контейнера Compose задаёт `/state` и `/output`; пути хоста могут быть абсолютными.
После изменения `.env` пересоздайте сервис через `docker compose up -d` или перезапустите
локальный процесс. Для новых путей сначала подготовьте каталоги и права.

[Полный справочник](docs/ru/CONFIGURATION.md): файловые секреты, явные зоны `BEGET_ZONES`,
DNS-серверы и таймауты, стабильность очистки и TTL TLS fallback.

## Типовые сценарии

### Один домен, wildcard или несколько имён

| Задача                                | `ACME_DOMAINS`                      |
| ------------------------------------- | ----------------------------------- |
| Один сайт                             | `example.com`                       |
| Домен и поддомены первого уровня      | `example.com,*.example.com`         |
| Только выбранные сервисы              | `api.example.com,files.example.com` |
| Несколько доменов в одном сертификате | `example.com,example.net`           |

Все зоны должны быть доступны через указанный аккаунт Beget. Они определяются автоматически;
при необходимости задайте `BEGET_ZONES`. Для IDN используйте punycode. CNAME-делегирование
challenge-имён не поддерживается. Перед сменой доменов завершите восстановление со старой
конфигурацией и остановите сервис; новый набор требует нового подтверждения.

### Nginx с автоматическим подхватом сертификатов

[Руководство Nginx](docs/ru/NGINX.md) содержит Compose, конфигурацию HTTPS и скрипт наблюдения.
Он проверяет `current` раз в час и вызывает reload только при изменении. Для разных пользователей
ACME и Nginx нужны общая TLS-группа, права прохода по каталогам и `ACME_PRIVATE_KEY_MODE=0640`.
Права ранее созданных ключей меняются отдельно. Сам ACME-сервис не перезапускает Nginx.

### Несколько независимых сертификатов

Запустите отдельный экземпляр на каждый сертификат с собственными `.env`, `state` и `output`.
Не допускайте пересечения challenge-имён: `example.com` и `*.example.com` используют одно имя.
[Пример двух сервисов](examples/compose.multiple.yml) и [инструкция](docs/ru/OPERATIONS.md#несколько-сертификатов).

### Cron, systemd и секреты из файлов

Для внешнего планировщика используйте `run --once`, без постоянного `run` одновременно.
Команда возвращает ошибку, если проверка не удалась или сохранённое время повтора ещё не наступило.
[Примеры systemd и cron](docs/ru/OPERATIONS.md#systemd-и-cron).

Вместо пароля в `.env` можно передать `BEGET_PASSWORD_FILE` и, при необходимости,
`BEGET_USERNAME_FILE`. Не задавайте одновременно значение и файл одного секрета.
[Настройка файловых секретов](docs/ru/CONFIGURATION.md#секреты).

## Диагностика

Для Docker после запуска сервиса:

```sh
docker compose logs --tail 100 beget-acme
docker compose exec beget-acme node dist/cli.js status --check
docker compose exec beget-acme node dist/cli.js doctor
```

Если сервис не запущен, используйте `docker compose run --rm beget-acme status --check`
или `docker compose run --rm beget-acme doctor`. Локально:

```sh
node --env-file=.env dist/cli.js status --check
node --env-file=.env dist/cli.js doctor
```

Добавьте `--staging` для диагностики тестового окружения.

| Ситуация                        | Что проверить                                                                                        |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `CONFIG_DOMAIN_REQUIRED`        | `.env` должен передаваться приложению: `env_file` в Compose или `node --env-file`                    |
| `Permission denied`             | UID/GID, права файлов и прохода по каталогам, ACL NAS; чтение ключа TLS-сервером                     |
| `OPERATION_LOCKED`              | Не запущен ли второй экземпляр с тем же state; не удаляйте файлы блокировки                          |
| `getData inventory unavailable` | API не дал список записей; это не подтверждение пустоты. Проверьте точное имя в панели               |
| Идут DNS-проверки или cleanup   | Ожидается распространение записей; очистка ждёт 45 секунд устойчивой пустоты на настроенных NS Beget |
| После запуска нет новых логов   | Посмотрите сообщение со временем следующей проверки: сервис может ждать сохранённый срок             |

`status --check` проверяет сертификат и состояние приложения, а не доступность сайта.
До первого выпуска контейнер может быть `unhealthy`. При незавершённой операции не удаляйте
журнал: [восстановление и ограничения](docs/ru/OPERATIONS.md#восстановление-после-остановки).

## Обновление

Сохраните резервные копии `state` и `output` со ссылками, владельцами и правами.
Для Docker выберите нужный тег из [релизов](https://github.com/zlooun/beget-acme/releases),
измените `BEGET_ACME_IMAGE` в `.env` и выполните:

```sh
docker compose pull beget-acme
docker compose up -d beget-acme
docker compose logs --tail 100 beget-acme
```

Не удаляйте state: там ключи аккаунтов и данные восстановления. Храните его на локальной
файловой системе, не SMB/NFS. Не запускайте старую и новую версии параллельно на одном состоянии.
