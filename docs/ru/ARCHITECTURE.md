# Архитектура

## Конфигурация и границы

`ACME_DOMAINS` задаёт точный список SAN одного сертификата. Setup определяет зоны
запросами к Beget для DNS-родителей; необязательный `BEGET_ZONES` заменяет автопоиск.
Выбирается наиболее длинная подтверждённая подходящая зона. Wildcard разрешён только
в левом крайнем сегменте. Для `example.com` и `*.example.com` используется одно имя
`_acme-challenge.example.com`, для `api.example.com` — отдельное имя.

Каждый экземпляр использует собственные `state` и `output`. У всех выбранных зон должны
быть настроены одни и те же `BEGET_NAMESERVERS`. CNAME-делегирование не поддерживается.

## Модули

- `src/cli.ts`: аргументы, коды выхода, обработка сигналов.
- `src/core/config.ts`: проверка конфигурации, секретов, зон и разрешённых имён.
- `src/core/application.ts`: выпуск, DNS-проверки и восстановление.
- `src/core/service.ts`: последовательный планировщик, сохранённые задержки и восстановление при старте.
- `src/core/response.ts`: чтение ответа Beget с ограничением размера и времени.
- `src/core/store.ts`: файловая блокировка, журнал, задержки повторов и публикация пары ключ/сертификат.
- `src/core/shutdown.ts`: отмена запросов и ожиданий без преждевременного снятия блокировки.
- `src/providers/beget.ts`: API Beget и независимый список разрешённых имён.
- `src/dns/verify.ts`: запросы ко всем заданным серверам, устойчивость результатов, часовой TTL адресов NS.
- `src/acme/`: JWS, nonce, ACME v2, проверка идентификаторов и генерация CSR.

Внешний JSON проверяется на границе. Ошибки содержат стабильные коды без сырых ответов
провайдера. Ошибки логируются в stderr, остальные события — в stdout.

## Выпуск и восстановление

1. Проверить разрешения, существующий сертификат, SAN и отсутствие незавершённого журнала.
2. Проверить все challenge-имена до создания ACME-заказа.
3. Получить заказ, проверить точное соответствие идентификаторов, собрать токены по именам.
4. Сохранить плановые имена в журнале; повторить preflight непосредственно перед записью каждого имени.
5. Последовательно записать TXT, сохраняя фазу до и после каждого запроса.
6. Дождаться правильных ответов authoritative и recursive DNS, сразу подтвердить challenges.
   Старые recursive-ответы повторно проверяются до таймаута; чужие authoritative-записи останавливают операцию.
7. Проверить SAN, сроки и соответствие ключа выданному сертификату, сохранить новую версию.
8. Очистить каждое затронутое имя; только подтверждённая очистка удаляет его из журнала.

Журнал версии 2 хранит первое имя на верхнем уровне и оставшиеся в `entries`.
Это позволяет читать предыдущий одноимённый формат. Фазы: `planned` — запрос ещё
не отправлялся; `prepared` — отправка могла произойти; `published` — запись подтверждена
API; `verified` — TXT проверены; `cleanup-started` — намерение удалить ранее проверенный собственный набор; `cleanup-requested` — удаление подтверждено API.
Неоднозначный ответ сохраняет журнал. Плановые, ещё не отправленные имена можно пропустить
при восстановлении. Чужие записи всегда блокируют удаление.

Повторный заказ с ранее подтверждёнными авторизациями может не требовать TXT. Preflight
всё равно выполняется: это осознанное консервативное ограничение, даже если CA могла бы
выдать сертификат при занятом challenge-имени.

`journal-clear` — аварийный операторский путь с подтверждением всех имён, причиной,
устойчивыми пустыми DNS-ответами и проверкой панели. Он архивирует журнал и не пишет DNS.
Ни один такой тест не исключает последующее применение ранее отправленного запроса провайдером.

## Продление и остановка

Один последовательный цикл: после успеха проверка через ACME_SCHEDULE_INTERVAL_MS
(12 часов), после любой операционной ошибки — через ACME_RETRY_INTERVAL_MS (1 час).
Retry-After CA может увеличить задержку. Лимита попыток нет. Режим и время следующей
проверки сохраняются между перезапусками. Перед новым выпуском выполняется безопасная
очистка журнала; чужие записи и неоднозначные мутации не обходятся. Ошибка восстановления
оставляет сервис работающим и ожидающим следующей попытки. --once делает одну попытку
и возвращает ошибку внешнему планировщику, включая ещё не наступившее время повтора.
ACME_RENEW_BEFORE_DAYS не задана — порог треть фактического срока; задана — ровно указанное
число дней. Продление начинается, когда оставшийся срок меньше порога. Явный порог больше
срока сертификата приведёт к продлению при каждой обычной проверке: выбирайте его осознанно.

Сигнал завершения отменяет ожидания и сетевые запросы; уже выполняющееся действие должно
завершиться или вернуть ошибку до снятия lock. DNS-запросы имеют собственные ограниченные
таймауты. При неизвестном результате записи журнал остаётся. `SIGKILL` не перехватывается.

В Linux указатель `current` переключается атомарным rename. В Windows замена junction
не атомарна: при ошибке rename восстанавливается резервная ссылка, а маркер позволяет
продолжить после аварии между переименованиями. Короткое окно отсутствия `current` остаётся. Это ограничение
следует учитывать при эксплуатации Windows как сервера сертификатов.

## Настройка и запуск сервиса

`src/core/setup.ts` проверяет каталоги, определяет зоны и проверяет DNS-имена.
Явное подтверждение сохраняется в `state/setup.json` и привязано к доменам, явно
заданным зонам, логину Beget, NS. Пароль туда не записывается.
Staging и production подтверждаются отдельно. Перед каждой записью остаётся preflight.
Перед изменением конфигурации остановите сервис и завершите восстановление со старой
конфигурацией. `run` использует подходящее подтверждение либо выполняет setup внутри
запуска при явном согласии через флаг/env, выпускает отсутствующий
сертификат и проверяет продление. `run --once` делает одну проверку; прежний
`schedule` требует существующий сертификат. Состояния повторов окружений разделены,
блокировка и журнал DNS общие.

## Владение операцией

`operation.sqlite` обеспечивает исключение параллельных операций через открытую транзакцию SQLite,
удерживаемую на всё время работы, включая сетевые ожидания. Закрытие соединения освобождает её;
при гибели процесса файловую блокировку освобождает ОС. Файл базы не удаляется. PID и имя хоста
используются только для диагностики. Требуется локальная файловая система.
Подробнее: [блокировки SQLite](https://www.sqlite.org/lockingv3.html).
Сервис завершает публикацию сертификата и восстанавливает DNS до применения сохранённого
расписания выпуска. Восстановление не создаёт заказ ACME и не отменяет задержку, установленную CA.
