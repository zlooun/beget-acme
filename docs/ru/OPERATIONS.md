# Эксплуатация

## Несколько сертификатов

Один экземпляр — один SAN-набор. Для независимых сертификатов используйте
[Compose для двух сервисов](../../examples/compose.multiple.yml). Создайте site-a.env и
site-b.env с разными ACME_DOMAINS, общим или разными аккаунтами Beget и явным согласием.
Создайте state-a, output-a, state-b, output-b с правами выбранного UID/GID.
Из корня репозитория запускайте docker compose --project-directory . -f examples/compose.multiple.yml up -d --build.
Не допускайте пересечения challenge-имён между сервисами: example.com и *.example.com
используют одно имя. Для rootless daemon учитывайте отображение UID на хосте.

## Готовый образ

[Compose без сборки](../../examples/compose.image.yml) использует BEGET_ACME_IMAGE из .env.
Укажите реально доступный образ и подготовьте каталоги. Из корня проекта используйте
--project-directory . -f examples/compose.image.yml во всех командах Compose.
После pull выполните run --rm beget-acme run --staging --once, затем up -d для production.
Политика unless-stopped возвращает сервис после перезапуска Docker. Журнал и проверки безопасности продолжают блокировать небезопасные операции даже при рестартах.

## systemd и cron

Примеры [service](../../examples/beget-acme.service) и [timer](../../examples/beget-acme.timer)
запускают run --once раз в час. Подготовьте пользователя beget-acme, собранный проект в
/opt/beget-acme и файл /etc/beget-acme.env, читаемый только этим пользователем.
Укажите ACME_STATE_DIR=/var/lib/beget-acme, ACME_OUTPUT_DIR=/var/lib/beget-certificates и
ACME_ACCEPT_DNS_REPLACEMENT=yes после проверки панели. Создайте каталоги с нужными правами.
Уточните путь node, установите units в /etc/systemd/system, выполните daemon-reload и
systemctl enable --now beget-acme.timer. Не запускайте одновременно timer и постоянный run.
--once не ждёт следующей попытки: RENEW_RETRY_DEFERRED возвращает ненулевой код,
следующее срабатывание таймера снова проверит сохранённую задержку. Окно часового таймера
может увеличить фактическое ожидание. Для cron используйте тот же абсолютный ExecStart
и перенаправьте stderr в контролируемый журнал.

## Перечитывание сертификата

После переключения current сервер должен перечитать пару. Используйте
[reload-if-changed.sh](../../examples/reload-if-changed.sh) на хосте TLS-сервера:

```sh
sh examples/reload-if-changed.sh /srv/certs/production/current/fullchain.pem /var/lib/beget-reload /usr/sbin/nginx -s reload
```

Запускайте независимо раз в минуту под пользователем с правом reload. Скрипт сравнивает
хеш сертификата и отмечает его только после успешной команды. Он не требует Docker socket
в контейнере ACME. Команда reload должна проверять конфигурацию согласно вашему серверу.
Маркер и lock хранятся в отдельном приватном каталоге. После аварии проверяйте stale lock
перед ручным удалением. При ошибке reload следующая проверка повторит его. Это работает
даже если сертификат уже сохранён, а очистка DNS ещё продолжается или завершилась ошибкой.

## Мониторинг и резервные копии

Контролируйте exit code status --check, состояние контейнера/таймера и срок сертификата,
который реально выдаёт TLS-сервер. Например openssl x509 -checkend 604800 -noout -in
/srv/certs/production/current/fullchain.pem даёт ненулевой код при сроке менее недели.
Свяжите эти проверки со своей системой уведомлений; приложение само не отправляет письма.
Сохраняйте резервные копии state/output с защитой приватных ключей. Старые версии
сертификатов автоматически не удаляются. Не удаляйте текущую версию и цели ссылок.

## Прокси и собственный CA

ACME HTTPS-транспорт напрямую использует Node HTTPS; HTTP_PROXY/HTTPS_PROXY не являются
поддерживаемым способом настройки этого транспорта. Не обещается работа через прокси.
Для доверенного корпоративного CA Node поддерживает NODE_EXTRA_CA_CERTS: файл должен быть
доступен процессу при старте (в контейнере подключите read-only). Никогда не отключайте
проверку сертификатов. Проверяйте вашу сетевую конфигурацию отдельно в staging.

## Восстановление после остановки

- Намерение изменить DNS сохраняется до запроса. Неотправленные записи `planned` безопасно удаляются из журнала.
- Перед новым выпуском сервис очищает TXT, принадлежность которых подтверждена журналом.
- Намерение удалить TXT сохраняется до вызова API. При потере ответа следующий запуск может
  подтвердить устойчивое отсутствие записей. Очистка проверяет все настроенные authoritative
  DNS Beget, без ожидания публичных кэшей. Интервал стабильности по умолчанию — 45 секунд.
- Перед переключением `current` сохраняются полная пара ключ/сертификат и маркер публикации.
  Следующая проверка выпуска валидирует пару и завершает переключение без нового заказа.
  Если `current` отсутствует или сломан, восстановление также проверяет полные локальные
  каталоги `cert-*` этого окружения: точные SAN, срок и соответствие ключа. Выбирается новейшая
  подходящая пара; неполные версии пропускаются. Повреждённый маркер архивируется только при
  наличии независимо проверенной пары, иначе восстановление останавливается.
  Непустой обычный каталог вместо `current` сохраняется для ручной проверки.
  Ошибка доступа не разрешает замену файлов или новый заказ.
- Ключ аккаунта сначала полностью записывается во временный файл, затем публикуется без замены
  существующего ключа. Оставшиеся временные файлы не используются как ключи.
- Блокировка — открытая транзакция SQLite через встроенный `node:sqlite`. ОС освобождает её
  при гибели процесса, включая SIGKILL. Возраст файла и PID не используются для захвата блокировки.
  Файл `operation.sqlite` остаётся на диске: нельзя удалять или заменять его при работающем сервисе.
  Оставшийся `operation-owner.json` содержит только диагностику и не мешает перезапуску.
- Восстановление выполняется до сохранённых задержек планировщика, не создаёт новых заказов ACME
  и не обходит срок повтора CA. Ошибки восстановления повторяются с настроенным интервалом ошибок.
- Если публикация не подтверждена, а DNS пуст, результат неоднозначен: Beget может применить запрос
  позже. Потерянный или повреждённый журнал, чужие TXT и некорректная пара сертификата не удаляются
  автоматически. Сервис продолжает повторы, но такие случаи могут потребовать вмешательства.

Храните state и output на постоянном диске. Принудительная запись файлов снижает риск частичных
записей, но не гарантирует восстановление после повреждения файловой системы или потери данных диском.

Для state используйте локальный диск: например, bind mount Docker на ext4/XFS или каталог NTFS
в Windows. Сетевые SMB/NFS-каталоги и одновременная работа старой и новой версий не поддерживаются.
Если остался старый каталог `operation.lock`, остановите все старые процессы, убедитесь, что
никто не использует состояние, затем однократно удалите этот каталог. Не удаляйте `operation.sqlite`.
SQLite встроен в используемую версию Node.js; отдельный сервер базы данных не нужен.
На POSIX изменения записей каталогов дополнительно синхронизируются с диском. На Windows
гарантии при отключении питания слабее: синхронизация каталогов здесь недоступна.

## Пользователь контейнера и права

USER в образе задаёт UID/GID 10001:10001 по умолчанию. Compose переопределяет его через
APP_UID/APP_GID без пересборки образа. Права bind-каталогов задаются на хосте: chown из
Dockerfile не меняет владельца подключённого каталога. Файлы secrets также должны быть
читаемы выбранным UID/GID; Compose не исправляет владельца файловых секретов.
Для постоянного staging-сервиса задайте ACME_ENVIRONMENT=staging, чтобы сервис и healthcheck
проверяли одно окружение. До первого выпуска healthcheck может быть неуспешным.

## DNS-проверки и устаревшие кэши

`example.com` и `*.example.com` используют `_acme-challenge.example.com`.
`api.example.com` и `*.api.example.com` используют `_acme-challenge.api.example.com`.
В панели DNS Beget проверяйте каждое точное имя, а не всю родительскую зону. Не удаляйте
чужие записи ради прохождения проверки. Не запускайте параллельно клиентов для этих имён.
`getData inventory unavailable` означает недоступность списка через API, а не пустую зону.
Проверка панели поэтому входит в осознанное согласие на замену DNS.

Перед проверкой CA все настроенные authoritative-серверы должны показывать точный набор
наших TXT. Чужие данные на них останавливают операцию. Старые ответы recursive-резолверов
считаются задержкой кэша: проверки продолжаются до таймаута. Очистка ждёт стабильной пустоты
только на configured authoritative-серверах. Эти проверки не гарантируют ответ из кэша CA.

## Диагностика и неоднозначное восстановление

`status`, `doctor` и `probe` доступны при отсутствующем, изменённом или повреждённом setup.
Они предупреждают о проблеме, но не дают прав записи. `status --check` возвращает ненулевой
код при некорректном разрешении. JSON-события ошибок содержат `code` и необязательный `hint`.
Для `cleanup` используйте исходную подтверждённую конфигурацию: диагностика нового набора
доменов не разрешает очистку старого.

`DNS_MUTATION_UNCERTAIN` сообщает имя, фазу и время журнала. Пустой DNS не доказывает, что
Beget позже не применит неподтверждённый запрос. Сохраните state, проверьте authoritative DNS
и панель, повторите cleanup. Если неопределённость сохраняется, используйте `journal-clear`
из [настроек](CONFIGURATION.md) с точными именами журнала и причиной ручной проверки.
Это осознанное решение оператора, а не автоматическое удаление журнала по таймауту.

## Общие сертификаты с TLS-контейнером

Создайте отдельную общую группу. Назначьте её GID основной группой процесса ACME и добавьте
TLS-контейнеру через `group_add`. Укажите `ACME_PRIVATE_KEY_MODE=0640`: настройка действует
на новые ключи, права существующих корректируются отдельно. Разрешите группе проход/чтение
каталогов output, включая будущие версии, и чтение пары сертификата. ACL NAS должны разрешать
проход в корень подключённого каталога. State и ключи аккаунта оставьте приватными.

Подключайте TLS-контейнеру всё дерево output только для чтения, а не один `current`, чтобы
переключение ссылки было видно. Пути внутри него: `production/current/fullchain.pem` и
`production/current/privkey.pem`. Проверяйте чтение с реальными UID/группами контейнера, не
выводя ключи. Копируйте резервные копии с сохранением ссылок, владельцев и прав: файловый
менеджер может превратить `current` в пустой каталог.
Reload выполняется отдельно TLS-сервером. Успешная отправка сигнала ещё не доказывает,
какой сертификат выдаётся клиенту: после обновления проверьте реальный endpoint.
