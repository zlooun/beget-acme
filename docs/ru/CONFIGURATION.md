# Настройки и дополнительные команды

## Основные параметры

| Переменная                          | Значение                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `ACME_DOMAINS`                      | Точный список SAN через запятую, максимум 100                            |
| `ACME_EMAIL`                        | Контактная почта ACME                                                    |
| `BEGET_USERNAME`, `BEGET_PASSWORD`  | Учётные данные API Beget                                                 |
| `ACME_ENVIRONMENT`                  | `production` по умолчанию; `staging` для тестового сервиса               |
| `BEGET_ZONES`                       | Необязательный список управляемых зон вместо автоматического определения |
| `ACME_STATE_DIR`, `ACME_OUTPUT_DIR` | Пути приложения; по умолчанию `./state`, `./output`                      |
| `STATE_DIR`, `CERTIFICATES_DIR`     | Пути хоста в Compose; внутри контейнера всегда `/state`, `/output`       |
| `APP_UID`, `APP_GID`                | Пользователь Compose, по умолчанию `10001:10001`                         |

`setup` сохраняет разрешение отдельно для staging и production. Подтверждение связано
с доменами, выбранными зонами, серверами, логином. Пароль не сохраняется
в setup-файле; его смена не требует повторного подтверждения DNS. Изменение каталога
сертификатов требует прав доступа, но не нового DNS-разрешения.

## Секреты

Вместо прямых значений поддерживаются `BEGET_USERNAME_FILE` и `BEGET_PASSWORD_FILE`.
Не задавайте одновременно значение и файл одного секрета. Начальный UTF-8 BOM и конечные
переводы строк удаляются; пробелы сохраняются. В `.env` значения с `#` заключайте в кавычки.

Для Compose есть [пример secrets](../../examples/compose.secrets.yml). Удалите прямые
credentials из `.env`, создайте `secrets/username.txt` и `secrets/password.txt`, ограничьте
доступ и разрешите чтение выбранному UID/GID. Запускайте Compose с двумя файлами:

```sh
docker compose -f docker-compose.yml -f examples/compose.secrets.yml run --rm beget-acme setup
```

Используйте ту же пару файлов при `up`, `run` и остальных командах. Compose secrets с
локальными файлами не заменяют защиту файлов и резервных копий на хосте.

## Дополнительные настройки

| Переменная                  | По умолчанию         | Назначение                                    |
| --------------------------- | -------------------- | --------------------------------------------- |
| `BEGET_NAMESERVERS`         | Четыре сервера Beget | Проверяемые authoritative DNS                 |
| `ACME_PUBLIC_RESOLVERS`     | `1.1.1.1,9.9.9.9`    | Recursive DNS; им видны запрашиваемые имена   |
| `ACME_DNS_TIMEOUT_MS`       | `900000`             | Таймаут ожидания одного DNS-имени             |
| `ACME_CLEANUP_SETTLE_MS`    | `45000`              | Непрерывное отсутствие TXT после удаления     |
| `ACME_RENEW_BEFORE_DAYS`    | не задано            | Треть срока или явный порог дней              |
| `ACME_RETRY_INTERVAL_MS`    | `3600000`            | Интервал после ошибки, 60000–86400000 мс      |
| `ACME_SCHEDULE_INTERVAL_MS` | `43200000`           | Пауза между успешными проверками              |
| `ACME_PRIVATE_KEY_MODE`     | `0600`               | Допустимо `0640` для настроенной общей группы |

Таймаут должен превышать интервал стабильности очистки более чем на 30 секунд.
Синхронизируйте часы хоста. Настройка CNAME-делегирования не поддерживается.

`--json` доступен для всех команд; ошибки пишутся в stderr. Флаги могут стоять до или
после команды. `run --once` выполняет одну проверку и подходит для cron/systemd timer.
`issue staging --dry-run` проверяет DNS без создания заказа и записи TXT.
`init` создаёт шаблон,
не перезаписывая существующий `.env`; `--version` показывает версию.

## Планировщик

Один последовательный цикл: после успеха проверка через ACME_SCHEDULE_INTERVAL_MS
(12 часов), после любой операционной ошибки — через ACME_RETRY_INTERVAL_MS (1 час).
Retry-After CA может увеличить задержку. Лимита попыток нет. Режим и время следующей
проверки сохраняются между перезапусками. Перед новым выпуском выполняется безопасная
очистка журнала; чужие записи и неоднозначные мутации не обходятся. Ошибка восстановления
оставляет сервис работающим и ожидающим следующей попытки. --once делает одну попытку
и возвращает ошибку внешнему планировщику, включая ещё не наступившее время повтора.
ACME_RENEW_BEFORE_DAYS не задана — порог треть фактического срока; задана — ровно указанное
число дней. Продление начинается, когда оставшийся срок меньше порога. Явный порог больше
срока сертификата приведёт к продлению при каждой обычной проверке: выбирайте его осознанно.

## Совместимость TLS для ACME

ACME использует встроенный HTTPS-транспорт Node с TLS 1.2–1.3. При таймауте
установления соединения (10 секунд), сбросе или некоторых ошибках согласования
до завершения рукопожатия выполняется один повтор с ограничением TLS 1.2.
Обе попытки разделяют общий таймаут запроса и сигнал остановки. Проверка сертификата
сервера остаётся обязательной. Ошибки сертификата, DNS, ответы HTTP и сбои после
рукопожатия не вызывают этот повтор. Beget продолжает использовать прежний транспорт.
Предупреждение о fallback не доказывает, что причиной сбоя была TLS 1.3.

После успешного fallback на TLS 1.2 выбор сохраняется по хосту ACME в `state/tls/`
и действует после перезапуска. Staging и production имеют разные хосты. Неудача обеих
попыток не сохраняет предпочтение. Для возврата к обычному согласованию TLS остановите
сервис и удалите только соответствующий файл предпочтения из `state/tls/`.
DNS-проверки используют ровно список BEGET_NAMESERVERS (по умолчанию четыре сервера
.com и .pro), а не все возможные NS Beget. Для расширения списка задайте его явно и
повторите setup после завершения recovery. В cleanup повторяются чтения DNS, а не удаления.

## Запуск без отдельного setup

run и schedule принимают --accept-dns-replacement или ACME_ACCEPT_DNS_REPLACEMENT=yes.
Значение по умолчанию — разрешение не задано. Флаг/env явно подтверждает замену записей
вычисленных DNS-имён и ручную проверку панели. При отсутствии подходящего разрешения
первоначальная настройка выполняется внутри запуска: права, зоны, пустота DNS и журнал.
Подходящее разрешение используется повторно без повторения setup. Повреждённый файл
разрешения не перезаписывается автоматически. Незавершённое восстановление блокирует
изменение области разрешения. Сохранённый setup без флага по-прежнему поддерживается.
Для первого выпуска используйте run; schedule требует существующий production-сертификат.
