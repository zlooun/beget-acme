# Nginx со встроенным наблюдателем сертификатов

Пример объединяет опубликованный образ ACME и `nginx-unprivileged` на Alpine. Наблюдатель
работает внутри Nginx: cron, Docker socket и сетевые команды от ACME не нужны.
Однократный `reload-if-changed.sh` остаётся альтернативой для внешнего таймера.

## Файлы и настройки

- [compose.image.yml](../../examples/compose.image.yml): сервис ACME.
- [compose.nginx.yml](../../examples/compose.nginx.yml): дополнение с Nginx и общей группой сертификатов.
- [nginx.env.example](../../examples/nginx.env.example): настройки обоих сервисов.
- [nginx-unprivileged.conf](../../examples/nginx-unprivileged.conf): HTTPS на порту 8443 внутри контейнера.
- [start-with-reload.sh](../../examples/start-with-reload.sh): запуск и наблюдение за версией.

Команды выполняйте из корня репозитория с `--project-directory .`. Создайте `.env` на основе
`examples/nginx.env.example` или дополните существующий файл, не перезаписывая рабочие
секреты. Заполните домены, email и учётные данные Beget. Измените `server_name`, замените
тестовый HTTP-ответ своей конфигурацией proxy и подключите необходимые Docker-сети.
Полный `.env` получает только ACME; Nginx передаётся интервал проверки, без секретов Beget.

Пути по умолчанию относительные к корню репозитория; абсолютные пути хоста тоже поддерживаются.
При переносе через файловый менеджер сохраняйте окончания строк LF. Скрипт запускается
через `/bin/sh`, поэтому достаточно права чтения, исполняемый бит не требуется. Пример
проверяется на указанном Alpine-образе и сохраняет его штатный entrypoint.

## Пользователи и права

По умолчанию UID ACME — 10001, UID/GID Nginx — 10003, общая TLS-группа — 10002.
Замените их на свои. Overlay назначает `TLS_GID` основной группой ACME и дополнительной
группой Nginx. Наличие пользователей с такими же именами внутри образов не требуется.

Для новой установки на обычном Linux-хосте Docker:

```sh
mkdir -p state output
sudo chown 10001:10002 state output
sudo chmod 700 state
sudo chmod 750 output
chmod 600 .env
```

При изменении настроек подставьте свои пути и ID. На NAS дополнительно проверьте ACL:
они должны разрешать проход и чтение всего подключённого дерева output. Владелец ACME
должен иметь запись, TLS-группа — чтение и проход, включая новые каталоги версий.
State оставьте приватным. Для rootless Docker или user namespace remapping учитывайте
отображение контейнерных ID в ID хоста.

Overlay задаёт `ACME_PRIVATE_KEY_MODE=0640` для новых ключей. У существующих ключей 0600
нужно отдельно скорректировать группу и права: переменная не переписывает их автоматически.
Не открывайте ключ всем пользователям. Монтируйте весь output, а не только `current` или PEM.

## Первый запуск

Сначала проверьте вычисленные `_acme-challenge` имена в панели Beget. Пока постоянные
сервисы не запущены, можно проверить staging:

```sh
docker compose --project-directory . --env-file .env -f examples/compose.image.yml -f examples/compose.nginx.yml run --rm beget-acme run --staging --once --accept-dns-replacement
```

Затем выпустите production и запустите сервисы:

```sh
docker compose --project-directory . --env-file .env -f examples/compose.image.yml -f examples/compose.nginx.yml run --rm beget-acme run --once --accept-dns-replacement
docker compose --project-directory . --env-file .env -f examples/compose.image.yml -f examples/compose.nginx.yml up -d
```

Альтернатива: после проверки панели включите `ACME_ACCEPT_DNS_REPLACEMENT=yes` и используйте
`up -d` также для первого выпуска. Nginx ждёт успешного healthcheck ACME; после выпуска
может потребоваться дождаться очередной проверки. Staging-сертификат не заменяет production
в этом примере. Последующая ошибка ACME не останавливает уже работающий Nginx автоматически.
Не запускайте отдельный контейнер выпуска параллельно с постоянным сервисом.

## Как работает наблюдатель

`NGINX_RELOAD_INTERVAL_SECONDS` по умолчанию равен 3600 (1 час); допустимы 1–86400 без ведущих нулей.
Скрипт запоминает цель ссылки `current` и запускает штатный entrypoint образа.
На каждом интервале сравнивает цель ссылки. Если версия та же — нет ни логов, ни reload.
При смене версии выполняются `nginx -t` и затем `nginx -s reload`. Ошибка проверки или
отправки сигнала логируется; следующая попытка будет через интервал. До успешного применения
Nginx продолжает использовать ранее загруженный сертификат. Файлы в `cert-*` неизменяемы:
правка PEM на месте без переключения `current` не обнаруживается.

По умолчанию `NGINX_CERTIFICATE_LINK` — `/etc/nginx/certs/production/current`. Для другого
пути измените и переменную скрипта, и директивы сертификата в Nginx. Отсутствие `current`
при старте завершает запуск ошибкой; во время работы оно логируется и проверяется повторно.

При остановке контейнера таймер завершается, Nginx получает QUIT для плавного завершения.
Неожиданное завершение Nginx обнаруживается примерно за секунду и даёт ненулевой код.
Наблюдатель — главная команда контейнера: его гибель тоже завершает контейнер, после чего
Compose сможет его перезапустить. Если соединения удерживают
завершение дольше `stop_grace_period`, Docker может принудительно остановить процессы.

Сообщение «Reload requested» подтверждает отправку сигнала, а не применение конфигурации
master-процессом. Nginx может откатить неудачный reload: следите за ошибками и проверяйте
реальный TLS-endpoint. Подробнее — [управление Nginx](https://nginx.org/en/docs/control.html).

`npm run test:nginx` проверяет пример в одноразовых Docker-контейнерах с самоподписанными
сертификатами: отсутствие лишних reload, реальную смену выдаваемого сертификата, повторы после
ошибок, гибель наблюдателя и плавную остановку. Ваш `.env`, state, сертификаты и API Beget не используются.
